# 会议提示词

当前提示词集中在 [server/ai/prompts.js](../server/ai/prompts.js)，可直接阅读和修改。`SYSTEM` 定义共同任务与事实边界，`ORGANIZE` 定义整理和追问的质量，`ANSWER` 定义问答质量；相应的 `*_CONTRACT` 单独规定页面存储需要的 JSON。

核心目标是：**帮助正在开会的人抓住少数真正影响下一步的事项。**

提示词遵循以下原则：

- 看问题是否值得此刻全员停下来，而不是看问题是否复杂。简单的协作冲突也可能重要；正在自然解释的细节、正常进度汇报和已有后续安排的事项，不必都成为焦点。没有逐字说明所有细节，不等于存在分歧。
- 一个条目表达一个持续演进的事项。同一问题的解释、补充和答案放在一起；重复条目可以归并，过程和来源留在历史。主题概述保留当前理解、关键限制和未决之处，已有表述仍准确时不为更新而重写。
- 追问沿用稳定 ID，承接已经得到的答案，聚焦剩余的关键差别。部分回答可以留下进展，只有核心疑问解除才退出当前讨论；结果性质与是否结束分别表达。
- 分开质量标准与输出格式。`impact` 说明具体影响，引用由程序核对；新问题数量是上限，不是产出目标。主屏可以推荐一个问题，也可以保持安静。
- 保留记录的事实边界：原话与推断、建议与明确决定、单方解释与共识、人工修正与 AI 更新。负责人汇报自己的安排不需要逐人附和，也不能扩大为全体共识。

输出中，`resolution.complete=false` 表示部分进展，问题仍活跃；`true` 表示核心疑问已解除。`outcome` 只描述结果性质。`mergedFollowups` 归并重复问题；`focusFollowupId` 指定当前推荐，`null` 表示不推荐。`summaryEvidence` 为完整当前概述提供依据，省略 `summary` 会保留旧概述。

输入装配见 [server/ai/context.js](../server/ai/context.js)：增量分析除新增转录外，还补充相关事项的既有依据、按问题检索的后续发言和邻近问答。生成纪要及强制重新分析时，会额外复核仍活跃或待核对的问题，检查已有回答、部分进展及重复关系；复核不新增问题。检索仍有上下文上限，未找到答案不能当作会上没有回答。

整理结果的引用会对照同一版本的完整会议原文核验，避免旧概述中的真实引用因未进入当前输入窗口而被误判无效。不存在的引用、其他会议的引用和对不上的原话仍会被拒绝。

会议问答在所选范围较短时读取完整原文；较长时，先由 `ANSWER_SELECT` 分段选择相关发言，再由 `ANSWER` 对照原话回答。各段均会参与选择，避免只按提问中的词语检索而漏掉不同时段的观点。主题问答限于该主题及子主题已有引用的原文。选择结果仍有数量和上下文上限，已阅读全部分段不代表不会遗漏有用的证据。

问答引用按实际交给回答模型的原文核验。引用对不上或实质回答没有引用时，会重新生成一次；仍失败则显示错误，不保存为「依据不足」。模型判断依据不足时应说明缺少什么。任务和回答中的 `coverage` 记录阅读范围、来源 ID 与版本、选择数量及因上下文上限未纳入的候选数量，便于复查；不额外复制原文。

给说话人补充或修改姓名只更新身份映射，保留已有讨论和分析进度。真正修改原文或某段发言的说话人归属时，相关内容才需要复核。已生成的历史文字不会被姓名替换操作批量改写。

## 用同一录音试提示词

1. 导入录音，完成转录，先检查人名、关键数字和否定词是否识别正确。
2. 在相同转录上执行“重新分析”。接口为 `POST /api/meetings/:id/jobs`，内容是 `{"type":"organize","force":true}`；MCP `organize_meeting` 对应 `type="organize", force=true`。
3. 对照原话看问题是否指出了实际差别、是否会影响当前选择，以及后续回答是否已经解除疑问。同时检查同一事项有没有重复拆分、概述是否丢失已有条件。一次安静的结果可以是好结果，不用追问数量代替价值判断。

`force` 会绕过“已整理至”的水位，从全部定稿转录重新分析。它保留原文、稳定 ID、主持人的修正和已有澄清记录；只增补或修订需要变化的内容。因此它适合迭代当前工作记录。如果要比较彼此不受旧 AI 结果影响的两次初始输出，可以把同一录音分别导入为两场测试会议。

每个 AI 任务可通过任务查询读取 `promptVersion`、`model`、`sourceRevision` 和 `modelCalls`。版本包含提示词内容的 SHA-256 指纹，修改后重启服务就会得到新版本。`modelCalls` 记录每次分析批次使用的模型、提示词版本与转录版本；不保存密钥。无需调用模型的任务，其 `model` 为 `null`，`modelCalls` 为空。

供应商成功返回但 JSON 或结构不合约时，同一批次最多重试一次，并记录 `modelCalls[].formatRetries=1`；仍不合约就停止，不发布部分批次结果。格式重试与网络重试共用最多三次请求，不保存原始错误响应。

较长录音仍按批次处理，以限制上下文大小；这是输入装配，不是要求模型照固定步骤思考。自动测试覆盖协议、来源校验、人工保护、重分析和任务隔离。它们不能证明追问的实际质量，后者需要用真实录音和参会者反馈判断。
