# 验证与试用

## 自动检查

在项目根目录运行：

```sh
npm run release:check
```

这会依次检查模块语法、运行自动测试、构建前端。录音导入相关测试会实际调用 ffmpeg，需要先安装。测试使用独立临时目录和模拟 ASR／LLM，不读取正式会议数据，也不需要云服务密钥。

当前测试覆盖：

- 录音保存、暂停恢复、尾段刷新、ASR 中断与采样位置。
- 文件导入、解码、分段转录、失败恢复和重复写入保护。
- 原文引用、人工修订保护、迟到 AI 任务和转录版本校验。
- 中性讨论记录、决定修订、问答依据不足和纪要导出。
- 事项归并、概述历史、部分回答与问题退出，以及会末复核期间的原文变化。
- 默认焦点跟随、阅读时停留、合并后的定位，以及当前条目和历史的分开展示。
- MCP 与 HTTP 对同一会议的读取和写回。

自动测试不证明真实语音识别准确率或追问质量。

## 页面检查

使用模拟会议依次检查以下场景：

1. 新建会议，或导入一段非敏感测试录音；核对录音、转录和 AI 整理各自的状态。
2. 在澄清焦点、大纲和导图间切换，核对所选主题、引用及人工修改。
3. 输入讨论记录后切换视图；遇到原文修正时，确认草稿保留，核对新原文后才能保存。
4. 点击原文引用，检查文字定位、音频区间和浮窗收起后的阅读位置。
5. 通过会议操作归档，再从侧栏进入已归档列表恢复。
6. 检查五套配色、窄屏、键盘操作和系统减少动态效果设置。
7. 让当前问题得到部分回答、完整回答，再手动放下一个问题；检查进展标记和下一焦点。展开依据时，后台切换推荐应保留阅读位置，点击“回到当前”恢复跟随。
8. 在同一主题下追加解释、修改结论；检查是否归回原事项，以及概述、旧条目和来源是否仍可从“讨论过程”查看。

导图目前仅绘制主题及父子归属。多个并列主题可以没有连线；跨主题的依赖、影响或分歧关系尚未实现。

## 同事首次使用

每位使用者需要在自己的电脑上配置服务地址、模型和凭证，并验证一次录音或导入。数据默认写入本机 `data/`；外部 ASR 和 LLM 会收到执行任务所需的音频或转录片段。

安装与启动见 [上手说明](GETTING_STARTED.md)。交付包不包含开发者的会议数据、凭证、截图和历史排障材料。

## 真实会议试用

会后记录少量能反映效果的事实：

| 项目 | 核对方式 |
| --- | --- |
| 找依据的耗时 | 对照工作台与纯转录，定位同一个问题的原话 |
| 会后修订量 | 统计需要更正的事实、决定、负责人和时间 |
| 追问的价值 | 记录采用了哪个问题，以及它改变了什么理解或选择 |
| 阅读干扰 | 记录跳动、遮挡、重复提示和投屏可读性 |
| 转录完整性 | 核对末句、暂停恢复、说话人与转录缺口 |

依据不足时保持安静是允许的结果；错误地宣告共识或覆盖人工修正应优先处理。
