# 本地声纹试验

固定团队登记声音后，新转录中的未命名说话人会在后台自动识别。多段结果一致、与其他成员差距足够大时采用姓名；不确定时等待更多发言或主持人确认。访客样本只在登记它的会议中比较，候选仍由主持人确认。自动识别不会登记新样本，运行时不可用时仍可手动标记。

## 会中流程与性能

火山负责转录和说话人分组，本地 CAM++ 负责将分组关联到成员。当前接入的[流式 ASR 公开文档](https://www.volcengine.com/docs/6561/1354869?lang=zh)提供 `enable_speaker_info`、`ssd_version` 等聚类参数，未提供会中写回某个 speaker 姓名的操作。因此工作台在本地保存分组与成员的映射，同一分组后续直接复用姓名。ASR 连接和录音段一起限定编号作用范围，暂停后继续或重连产生的新分组重新核对。

导入录音使用火山文件接口，已启用说话人分离和句级输出。新任务在请求大小、时长限制内整段识别，超限才分长段；当前 WAV 格式每段约 52 分钟。独立请求的分组编号仍各自隔离，不按相同编号直接合并。整段识别可以减少一分钟分段造成的重复分组，但不代表分离结果或团队姓名识别一定准确。

- 只处理新转录所在会议中尚未命名的真实 ASR 分组，不扫描历史会议。ASR 没有分出人的 unknown 发言不会当作同一个人。
- 累积至少两段准确定位、无已知重叠的发言，每段至少 3 秒、转录至少 4 个字母或数字字符；空格、标点不计。最长使用每段前 30 秒。
- 新转录合并为后台检查，默认间隔 3 秒。一次选 2–4 段，全局串行运行，每个 Python 进程使用 2 个 CPU 线程，不阻塞音频保存和 ASR。
- 未认出时等新的合格发言，至少间隔 30 秒，每个分组最多自动尝试 4 次。主持人可点重新识别重置本人的尝试次数。
- 相同音频、来源版本和模型的特征会复用；每个分组最多缓存 8 段。匹配时只复用 4 个临时 PCM 槽位，不为每次尝试永久复制录音。
- 人工标记后不再自动改名。任务完成时重新核对发言、成员和样本状态，防止迟到结果覆盖修正。识别状态保存在服务端，关闭窗口后仍继续运行。

## 安装与验证

在项目目录执行：

```sh
python3 scripts/setup-voiceprints.py
```

脚本优先使用已安装的 `uv` 建立 Python 3.12 隔离环境；没有 uv 时，可以用 Python 3.10–3.13 执行。默认目录为 `data/voiceprint-runtime`，通过 `WORKBENCH_VOICEPRINT_RUNTIME` 或 `--runtime-dir` 指定其他位置。服务端和安装脚本需使用同一个目录。

依赖固定为 PyTorch 2.7.1、torchaudio 2.7.1 和 NumPy 2.2.6。模型权重约 28 MB，首次还需下载 Python 依赖。安装验证只下载官方公开的三个演示音频，不读取会议录音；结果写入运行时的 `manifest.json`。日常运行无需连接模型提供方。

模型为 `funasr/campplus`，固定 revision 为 `e4b6ede7ce16997aff4ae69fbca1f0175e2afede`，权重 SHA-256 为 `3388cf5fd3493c9ac9c69851d8e7a8badcfb4f3dc631020c4961371646d5ada8`。运行时使用官方 3D-Speaker 的 CAM++ 结构，固定代码 revision 为 `065629c313eaf1a01c65c640c46d77e61e9607b4`，保留其 LICENSE 与模型卡。源代码和模型标注 Apache-2.0。

官方来源：[模型卡](https://huggingface.co/funasr/campplus)、[模型结构与独立推理](https://github.com/modelscope/3D-Speaker/blob/main/speakerlab/bin/infer_sv.py)。

## 选择样本

主持人先确认说话人，再从原文选择 2–4 段发言，每段至少 3 秒、至少 4 个字、总计至少 6 秒。长发言只使用前 30 秒，预览和提特征采用同一区间。团队样本还必须关联已确认的团队成员。需要先回听，选择没有他人插话、杂音或明显失真的单人语音。

只接受已保存的 16 kHz 单声道 PCM，并按转录的 `startSample` / `endSample` 读取。尚未明确归属的未知发言、人工补写而没有录音位置的原文、只有整块时间的转录，以及所取区间与其他人的已知发言重叠的样本都不能用于登记。原始标签为 unknown 的发言，在通过逐条修正明确归属后可以使用。程序会检查静音、严重削波和段间声纹差异；这些检查不能保证片段绝无串音，主持人的回听仍然必要。

登记的声音片段、特征、来源位置、人工确认的归属和模型版本保存在 `data/voiceprints` 私有目录中，保留团队或单场会议的作用范围。打开「说话人 → 团队成员」可查看来源、回听片段、停用或重新启用。停用保留资料，但不再参与匹配；来源归属或录音区间被更正时显示不可用原因。

## 建议的含义

运行时只在 CPU 子进程中计算 192 维声纹向量。Node 服务通过串行后台任务读取样本、启动计算，并支持取消和超时；不在采集线程内运行模型。

结果中的 `score` 是余弦相似度，不是身份概率。候选最低分为 0.5。自动采用只面向团队成员：至少两段各自匹配到同一人，每段及合并结果分数不低于 0.8、与第二位不同成员的差值不低于 0.15，片段间一致性不低于 0.7。只有一位可用成员时，差值按与零相似度的差额计算，结果会标明该情况。较弱的候选不自动采用。条件集中在 `shared/voiceprint-policy.js`，是尚未完成真实团队校准的试用阈值，始终保留 `calibrated: false`。

应当用不同会议、设备和环境的真实片段进行人工对照，分别观察误认、拒识、短句与重叠发言；公开演示音频的运行成功不能替代这一步。模型更新后旧向量不会与新版本混合比较。来源重新归属或录音区间修改后，相应登记资料不再作为候选依据。

## 服务接口

`createVoiceprintService({ store })` 位于 `server/voiceprints/service.js`，不使用 AI 分析任务队列。

- `status()`：运行时是否可用、模型版本、样本要求、未校准状态。
- `submit('enroll' | 'match', { meetingId, participantId, sourceIds, scope })`：返回独立任务，`scope` 为 `meeting` 或 `team`；团队成员从已确认的 participant 读取。
- `getJob(id)`：返回 `queued`、`running`、`done`、`error` 或 `cancelled`，完成结果在 `result` 中。
- `cancelJob(id)`：取消排队或运行中的任务。
- `listProfiles({ meetingId, includeUnavailable })`：团队资料和本会访客资料，可带不可用原因及安全回听区间，不返回原始向量或音频路径。
- `setProfileEnabled(id, enabled)`：停用或重新启用登记资料。
- `selectSamples(meetingId, participantId, { automatic, excludeSourceIds })`：自动选择合格片段，无需界面逐段勾选。
- `listJobs({ meetingId, limit })`：恢复窗口关闭前的登记与识别状态。
- `stop()`：停止接收任务并取消未完成任务。

登记结果包含 `profile`。匹配结果包含 `candidates`、逐段 `segmentMatches`、试用条件 `policy` 和可自动采用的团队候选 `autoAccept`。纯 `voiceprints/match` 只返回比较结果；`automatic.js` 统一执行新转录识别及指定说话人重试，在校验通过后通过 people store 采用姓名，身份来源记为 `voiceprint`。主持人编辑则记为 `manual`。采用姓名后，带身份引用的观点立即显示姓名，旧文本的归属核对通过独立 AI 任务更新并保留原内容。
